# Правила оформления русского перевода

Эти правила применяются к нашим `data/corrections.json` и к будущей ручной
ревизии строк. Они не являются основанием для автоматического изменения
регистра всего официального перевода.

## Sentence case для русского UI

- Самостоятельная кнопка, пункт меню, вкладка, заголовок или полноценная
  интерфейсная подпись начинается с прописной буквы.
- Одиночные UI-слова: «Назад», «Сохранить», «Настройки», «Звук».
- В многословной строке первое слово начинается с прописной, остальные
  оформляются по обычным правилам русского языка: «Создать или возобновить
  игру», «Восстановить все настройки».
- English Title Case, то есть прописная у каждого значимого слова,
  для русского UI не используется.
- Регистр английского source сам по себе не определяет регистр русского
  перевода. Например, самостоятельная кнопка с source `back` переводится
  как «Назад», а не «назад».
- Имена собственные и аббревиатуры оформляются по своим правилам.
- Строка может начинаться со строчной, если доказано, что она является
  продолжением другого текста. Сам по себе регистр source этого не доказывает.
- ALL CAPS сохраняется только когда это явно обусловлено дизайном или
  контекстом интерфейса.

## Контекст и ручная ревизия

При выборе формулировки и регистра учитывать назначение строки в интерфейсе,
английский source и связанные подписи. Изменять только проверенные corrections;
не применять массовое преобразование регистра к официальным EN/RU ресурсам.

Первое подтверждённое исправление: `Content<TAB>1408111756`, source `back`,
официальный RU «спина», correction «Назад». Это самостоятельная кнопка возврата
внизу по центру экрана выбора режима.

Контекст интерфейса или предмета имеет приоритет при выборе значения
многозначного английского слова; одного source text недостаточно. Например,
`Hide Hat` — предмет одежды: `hide` означает кожу, поэтому «Кожаная шапка»,
а не команда «Скрыть головной убор».
